02 Five Permission Layers

One engine, one cache, five coordinated enforcement points.

1 · Feature

feature:analytics · feature:billing

Coarse module toggle. Used for paid plans, beta features, soft launch.

Enforced by: *hasFeature directive, featureGuard

2 · Screen

screen:admin.users.list · screen:admin.audit

Maps 1:1 to a route. Hide entire pages.

Enforced by: permissionGuard() on routes

3 · Component

component:user.deleteBtn

Hide buttons, disable tabs, mask fields at fine grain.

Enforced by: *hasPermission directive

4 · Action

users:user:create · posts:post:publish

Domain-level capability. The bread-and-butter of API authz.

Enforced by: requirePermission() middleware

5 · Database

db:projects:row.read.own

Row/column level. BOLA / IDOR defense.

Enforced by: Query builder + PostgreSQL RLS

Wildcards

users:*:create · *:user:read

Glob-style. Use sparingly — every wildcard is a hole in the audit story.

Single check vs bulk

// Single
const { allowed, source } = await engine.check(userId, orgId, 'users:user:create');
//  source ∈ 'role' | 'inherited' | 'deny' | null

// Bulk — one resolve, many answers
const { results, version } = await engine.checkMany(userId, orgId, [
  'users:user:create',
  'users:user:delete',
  'feature:analytics'
]);

Resolution guarantees

  • Deterministic — same inputs always produce same output.
  • Cycle-safe — DB trigger rejects; service pre-checks for fast fail.
  • Bounded — depth ≤ 8, O(R + P) where R = effective roles, P = permissions.
  • Tenant-isolated — every query scoped by organization_id.
  • Cache-coherent — cache key includes policy_version, so any mutation self-invalidates.

05 Caching Strategy

L0 · Browser memory (signals)

TTL: session

Key: PolicyStore signal

Reactive, automatic. Invalidated when the interceptor sees a new X-Policy-Version.

L1 · In-process LRU

TTL: 60 s

Key: rbac:policy:{org}:{user}:v{ver}

Cap: 10,000 entries

Sub-millisecond. Cleared on policy change via pub/sub.

L2 · Redis

TTL: 300 s

Negative cache: 60 s for explicit denies

Shared across instances. Single-flight SETNX lock prevents stampede.

Invalidation

Any mutation → DB trigger bumps policy_versions → service publishes on rbac:invalidate:{orgId} → all instances drop L1.

Effective invalidation time: < 1 s globally.

07 Angular Layer

Code example — three patterns

<!-- 1. Directive (declarative) -->
<button *hasPermission="'users:user:delete'" (click)="del(u)">Delete</button>
<a      *hasRole="'org_admin'" routerLink="/admin">Admin</a>
<billing-panel *hasFeature="'billing'" />

<!-- 2. Signal (programmatic) -->
@if (rbac.can('users:user:create')()) {
  <create-user-btn />
}

<!-- 3. Guard (route) -->
{
  path: 'admin/audit',
  canMatch: [permissionGuard('screen:admin.audit')],
  loadComponent: () => import('./audit/audit.component')
}

09 Audit Logging

What gets logged

  • All permission denials (100%)
  • Role create / update / delete
  • Permission grant / revoke
  • Inheritance add / remove
  • User role assign / revoke
  • Bulk operations with affected count
  • Impersonation, export, sensitive admin actions

10 Security Model — Defense in Depth

Six layers of defense

  1. Network — WAF, rate-limit, IP allowlist for admin
  2. Auth — JWT verify, MFA for sensitive ops
  3. Authz — Permission Engine on every endpoint
  4. Query — Resource scopes injected into query builder (BOLA defense)
  5. DB — Row-level security as last-resort filter
  6. Audit — Hash-chained log of every decision

Threat model
